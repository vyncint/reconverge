# RC005 — launch-contract inconsistency

The kernel's index arithmetic assumes a launch shape that its
`#[launch_contract]` contradicts — or the kernel uses a shape-dependent
index formula and declares no contract at all.

## A minimal failing kernel

```rust
#[kernel]
#[launch_contract(domain = 2, coordinates = u32, block = (16, 16, 1))]
pub fn mismatch(mut out: DisjointSlice<f32>) {
    let i = thread::index_1d(); // RC005: 1D formula under a 2D contract
    if let Some(e) = out.get_mut(i) {
        *e = 3.0;
    }
}
```

And the quieter variant: `thread::index_1d()` with **no** contract, so
nothing checks the launch site's shape against the kernel's assumption.

## What happens on hardware

Nothing crashes — that is the problem. The index formula bakes in an
assumption about how the grid and block are shaped; the contract is what
lets the launch site be checked against that assumption. When they
disagree (or the contract is missing), a mismatched launch compiles and
runs: threads compute indices outside the domain the kernel meant, and the
result is skipped elements, doubly-processed elements, or out-of-range
indices that a bounds check silently discards. The output is wrong in ways
that scale with the launch configuration, which makes it exquisitely hard
to reproduce.

## The fix

Declare a contract that matches the index formula, so launches are checked
against the kernel's real assumption:

```rust
#[kernel]
#[launch_contract(domain = 1, coordinates = u32, block = (128, 1, 1))]
pub fn contracted(mut out: DisjointSlice<f32>) {
    let i = thread::index_1d();
    if let Some(e) = out.get_mut(i) {
        *e = 5.0;
    }
}
```

Or use the proof-carrying `*_u32` index variants, whose domain is enforced
by the type system and needs no separate declaration.

## Notes

- Reported at `warning` confidence (shown with `--strict`): the mismatch is
  real, but whether a given launch actually trips it depends on the host
  side, which this tool does not see.
- The domain is read from the index call the `#[kernel]` macro generates,
  so the check tracks what the kernel *does*, not what a comment says.
- SIMT fundamentals: `cargo reconverge learn` ships four interactive
  lessons (divergence, barriers, masks, reconvergence), fully offline.

# RC002 — warp collective at a non-convergent point

A warp collective (`ballot_sync`, `any_sync`, `all_sync`, `shfl_*`,
`match_*_sync`) executes at a point some lanes of the warp may never reach,
while its participation mask still names those lanes.

## A minimal failing kernel

```rust
#[kernel]
pub fn divergent_collective(mut out: DisjointSlice<u32>) {
    let i = thread::index_1d();
    let mut vote = 0u32;
    if i.get() % 2 == 0 {
        // RC002: the mask names all 32 lanes, but odd lanes never arrive
        vote = warp::ballot_sync(0xffff_ffff, true);
    }
    if let Some(e) = out.get_mut(i) {
        *e = vote;
    }
}
```

## What happens on hardware

The `*_sync` collectives synchronize **exactly the lanes named in the
mask**: every named lane must eventually execute the same collective, and a
lane must always be a member of its own mask. Here the mask promises all 32
lanes, but the branch only lets even lanes arrive. That breaks the
contract, and the result is undefined behavior — a hang, or worse, a
*silently wrong value* (a ballot missing half its voters, a shuffle reading
garbage) that propagates into your results with no diagnostic anywhere.
This is the failure mode cuda-oxide's own documentation calls "the worst
kind of bug", because nothing crashes.

Threads of a warp do not execute in guaranteed step with each other, so
whether the non-arriving lanes make this hang or silently misbehave can vary
run to run and between compute capabilities.

## The fix

Either move the collective to a convergent point, where every lane of the
warp executes it:

```rust
let vote = warp::ballot_sync(FULL_MASK, i.get() % 2 == 0); // convergent
```

— note how the *condition* moves into the collective's argument instead of
guarding it — or, when partial participation is intended, make the mask name
exactly the lanes that take the branch:

```rust
let lane = thread::lane_id();
if lane < 16 {
    // OK: the mask names exactly the 16 lanes that arrive
    let vote = warp::ballot_sync(0x0000_ffff, flag);
}
```

The mask and the control flow must tell the same story; either one alone is
not enough.

## Notes

- Reported as `confirmed` when the witness interpreter replayed the
  mismatch with a concrete constant mask and lane set; as `warning` when
  the mask is computed at runtime or the divergence is conservative static
  reasoning (shown with `--strict`). A constant mask that exactly matches
  the arriving lanes is not flagged.
- The provenance chain walks the divergent condition back to its source;
  `cargo reconverge inspect` navigates it interactively.
- Lesson: `cargo reconverge learn` — lesson 3 (*masks*) replays this exact
  mismatch, the mask drawn against the lanes that actually arrive.
